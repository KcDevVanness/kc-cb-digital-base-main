# 关联字段选择器改为「下拉 + 搜索」

## 背景与问题

**官方页面**里所有指向另一条记录的字段（销售单据的客户 / 渠道、单据行的商品 / 行状态、客户详情的
角色分配用户……）都由框架组件 `LookupSelect` 渲染（本仓自建表单用的是另一种组件 `ComboboxInput`，
本来就是下拉 + 搜索，见下）。它的交互是**纯搜索**：`minQuery` 默认 2，
不输入够字符就不发请求、不显示任何选项，只显示「开始输入以搜索。」；展开后结果还是输入框
下方的内联大卡片列表，会把表单顶开。

后果：**不熟悉系统的人无法先看有什么、再选**。他必须事先知道客户名称、商品标题、渠道编码
才能开始找；新建流程里字段看起来像空的搜索框，编辑流程因为已带值反而正常，所以问题只在
「新建 + 不了解数据」时暴露，试用和培训阶段最痛。

调研结论（2026-09-21，证据见下）：

- 该形态来自框架包 `@open-mercato/ui` 的 `LookupSelect`（0.8.0，`backend/inputs/LookupSelect.tsx`
  `:53` 默认 `minQuery = 2`，`:129` 的 `shouldSearch` 闸门）。本仓 `src/**` **零调用点**，
  catalog / wms 等模块用的是另一种组件 `ComboboxInput`（本来就是下拉 + 搜索）。
- **数据层没有阻塞**：所有选项源接口都接受空 `search` 并返回有界首页（`makeCrudRoute` 把
  pageSize 夹在 1..100；状态字典与 `/api/currencies/currencies/options` 同理）。
- **app 侧改不动**：组件覆盖机制只认 `page:`/`data-table:`/`crud-form:`/`section:` 四种句柄，
  输入类组件没有句柄，且 `crud-form:`/`data-table:` 在 0.8.0 只是 DOM 标记
  （见 `.ai/lessons/installed-inputs-have-no-component-override.md`）。
- 因此修复面在上游。已产出可应用补丁与验证工具链：`.ai/analysis/lookup-select-dropdown/`。

## 目标 / 非目标

**目标**

1. 新建流程中，不输入任何字符即可看到首页选项（下拉面板），输入即过滤（保持服务端搜索与
   防抖），键盘 / 清空 / 已选可见等既有语义不退化。
2. 不引入调用方改动、不新增 i18n key、不改变写入值与 API 契约。
3. 交付一个可被上游直接接受或内部发布的补丁，本仓只做版本升级 + 回归。

**非目标**

1. 不在本仓复制 / 覆盖框架页面来「假装修好」（`page:` 覆盖要重写销售开单等大页面，且随升级漂移）。
2. 不改领域层：entity、`makeCrudRoute`、命令、ACL、事件、迁移一律不动。
3. 不顺手改 `LookupSelect` 的卡片样式、图标或文案体系。

## 用户与场景

| 用户 | 场景 | 今天的失败方式 |
|---|---|---|
| 新上手的内勤 / 销售 | 新建销售单据，选客户、渠道 | 不知道客户在系统里的名字 → 搜索框没有可浏览的选项 |
| 仓配 / 客服 | 单据行选商品、行状态 | `minQuery=1`，一个字符都不输时列表不可见 |
| 系统管理员 | 客户详情里给角色换人 | 需要先知道用户邮箱才能搜到人 |

## 验收标准

1. 新建流程：聚焦（或点击、或 `↓`）即出现首页选项；输入后按既有 220ms 防抖做服务端过滤。
2. 选中后：面板关闭、搜索框清空、选中项仍可读（摘要行或宿主自己的标签），**任何情况下不把
   UUID 渲染成标签**。
3. 键盘：`↓`/`↑` 移动、`Enter`/`Space` 选中、`Escape` 关闭并清查询且不冒泡到外层对话框、`Tab` 离开；
   焦点顺序与 `aria-expanded`/`aria-controls`/`aria-activedescendant` 语义保持。
4. 显式传 `minQuery ≥ 1` 的调用点仍保持「类型搜索」：阈值以下不发请求并显示阈值提示。
5. `disabled` 字段仍可读、完全惰性（无列表交互、无清空、无 action slot）。
6. 一屏多个关联字段时，**未交互不发任何选项请求**；页面对比改动前请求数不增加。
7. 窄屏：面板跟随输入框宽度、可滚动，周围表单不跳版。

## 开放问题

1. `defaultOpen`（通知偏好、发运地址两处）在面板形态下是否要沿用「挂载即展开」？补丁取
   「挂载预取、按意图展开」，避免自动浮层盖住对话框——若产品坚持要挂载即见列表，可让这两处传
   `variant="inline"`。
2. eudr 等内联布局站点（本部署未启用）是否需要在升版后逐个确认保持 `variant="inline"`。
3. 后续是否推动上游补 `input:` 覆盖句柄，以及 `customers/addresses`、`dictionaries/{id}/entries`
   的 `search` 参数（两者今天只能客户端过滤）。
