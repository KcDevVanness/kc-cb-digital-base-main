# 跨境 ERP：采购 / 跨境发运 / 平台结算

> 这是**产品需求**（要解决什么问题、给谁用、验收标准）。实施阶段、任务拆解、进度与交接须知在
> [`../plans/cross-border-erp.md`](../plans/cross-border-erp.md)；系统归属与模块地图在
> [`../dev/business-architecture.md`](../dev/business-architecture.md)。

## 背景与问题

公司业务是"国内采购 → 卖给海外分公司 → 分公司做跨境电商"：国内主体向代理商进货，货物**直发**海外仓，
海外分公司在电商平台上销售，平台按周期回款并扣佣。业务现状与平台能力的差距：

- 平台（Open Mercato）已提供商品主数据（含 HS/CN、原产国、重量尺寸等跨境字段）、客户、对分公司的销售单据链
  （报价→订单→发货→退货→发票→贷项→收款）、多仓库存台账（仓库/库位/批次/余额/预留/移动/盘点）、币种汇率、组织树。
- 平台**没有**：采购（供应商/采购单/付款）、跨境发运与在途、出口单证、平台订单与结算对接。这三块目前只能线下或用 Excel 处理，
  导致"订了什么、发到哪了、该付多少、平台回了多少"无法在系统里闭环。
- 海外分公司的库存与上下架以**电商平台**为准，海外仓（3PL）另有 API，两者数据完整度未知；本系统必须明确"谁是账本"。

## 目标 / 非目标

**目标**

1. 三条链在系统内闭环并可追溯：**采购链**（采购单→定金/尾款→发运→海外仓收货→应付结清）、**跨境链**（发运单/在途/出口单证→海外仓入库）、**平台链**（平台订单/库存/结算数据同步→对账）。
2. 账实一致：库存账以本系统 `wms` 为准，平台与 3PL 的 API 只作同步输入，差异进对账队列，**不静默覆盖**。
3. 多主体可见性正确：总部看全部下级，分公司只看自己，不能向上、不能同级。
4. 全部界面中文可读（先中英双语），权限按功能位 fail-closed。

**非目标**

- 不接 EUDR（不卖欧盟）；不做采购审批流与账期/账龄；不做国内仓库节点；不做平台库存回写（除非未来单独立项）；
  不 eject 官方模块；不复建仓库台账、对分公司销售单据链（**商品主数据改为自建 `products`**，见 E 段与
  [业务架构](../dev/business-architecture.md)）；**交易对手方主数据改为自建 `parties`**（2026-09-22 决策，见 G 段），
  官方 `customers` 保留启用只为满足 `sales requires customers` 与历史单据；**不做生产制造**（无 BOM / 工单 / 工序 / 成本核算，见 E-10）。

## 用户与场景

| 角色 | 组织范围 | 场景 |
|---|---|---|
| 总部采购员 | 总部（+后代） | 建供应商、下采购单、登记定金/尾款、跟踪发运与到货 |
| 总部财务 | 总部 | 核对采购付款与应付余额、登记平台回款与费用 |
| 总部单证/物流 | 总部 | 生成发运单与出口单证、维护在途里程碑、录入货代信息 |
| 海外仓管 | 本分公司 | 确认到货入库（`wms` 收货）、盘点、退货入库 |
| 分公司运营 | 本分公司 | 查看本组织的订单/库存镜像、平台结算对账结果 |
| 集团管理层 | 全部组织 | 汇总视图（采购/在途/库存/回款） |
