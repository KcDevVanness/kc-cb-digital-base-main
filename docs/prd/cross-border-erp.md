# 跨境 ERP：采购 / 跨境发运 / 平台结算

> 这是**产品需求**（要解决什么问题、给谁用、验收标准）。实施阶段、任务拆解、进度与交接须知在
> [`../plans/cross-border-erp.md`](../plans/cross-border-erp.md)；系统归属与模块地图在
> [`../dev/business-architecture.md`](../dev/business-architecture.md)。

## 背景与问题

公司业务是"国内采购 → 卖给海外分公司 → 分公司做跨境电商"：国内主体向代理商进货，货物**直发**海外仓，
海外分公司在电商平台上销售，平台按周期回款并扣佣。业务现状与平台能力的差距：

- 平台（Open Mercato）已提供商品主数据（含 HS/CN、原产国、重量尺寸等跨境字段）、客户、对分公司的销售单据链
  （报价→订单→发货→退货→发票→贷项→收款）、多仓库存台账（仓库/库位/批次/余额/预留/移动/盘点）、币种汇率、组织树。
- 平台**没有**：采购（供应商/采购单/付款）、跨境发运与在途、出口单证、平台订单与结算对接。这三块目前只能线下或用 Excel 处理，
  导致"订了什么、发到哪了、该付多少、平台回了多少"无法在系统里闭环。
- 海外分公司的库存与上下架以**电商平台**为准，海外仓（3PL）另有 API，两者数据完整度未知；本系统必须明确"谁是账本"。

## 目标 / 非目标

**目标**

1. 三条链在系统内闭环并可追溯：**采购链**（采购单→定金/尾款→发运→海外仓收货→应付结清）、**跨境链**（发运单/在途/出口单证→海外仓入库）、**平台链**（平台订单/库存/结算数据同步→对账）。
2. 账实一致：库存账以本系统 `wms` 为准，平台与 3PL 的 API 只作同步输入，差异进对账队列，**不静默覆盖**。
3. 多主体可见性正确：总部看全部下级，分公司只看自己，不能向上、不能同级。
4. 全部界面中文可读（先中英双语），权限按功能位 fail-closed。

**非目标**

- 不接 EUDR（不卖欧盟）；不做采购审批流与账期/账龄；不做国内仓库节点；不做平台库存回写（除非未来单独立项）；
  不 eject 官方模块；不重建商品主数据、客户主数据、仓库台账、对分公司销售单据链。

## 用户与场景

| 角色 | 组织范围 | 场景 |
|---|---|---|
| 总部采购员 | 总部（+后代） | 建供应商、下采购单、登记定金/尾款、跟踪发运与到货 |
| 总部财务 | 总部 | 核对采购付款与应付余额、登记平台回款与费用 |
| 总部单证/物流 | 总部 | 生成发运单与出口单证、维护在途里程碑、录入货代信息 |
| 海外仓管 | 本分公司 | 确认到货入库（`wms` 收货）、盘点、退货入库 |
| 分公司运营 | 本分公司 | 查看本组织的订单/库存镜像、平台结算对账结果 |
| 集团管理层 | 全部组织 | 汇总视图（采购/在途/库存/回款） |

## 功能需求（按模块，逐条可验收）

### A. purchasing（已完成主体，剩余见计划）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| A-1 | 供应商主数据 | 组织内编码唯一（含已软删记录）；默认币种必须来自**币种字典**；停用后不出现在选择器 |
| A-2 | 采购单与明细 | 每组织唯一单号（`PO-<年>-<4位>`，下单时分配）；行引用商品 id + 快照；行税率 + 含税开关；净额/税额/总额推导正确 |
| A-3 | 状态机 | `draft→placed→shipped→received→closed`，`cancel` 仅 draft/placed 且**必填原因**；非法流转 422 且状态不变 |
| A-4 | 阶段付款 | 定金/尾款/其他，可多次部分支付；付款币种必须等于订单币种；付款状态与未付额**由付款行推导** |
| A-5 | 并发与审计 | 更新/删除带版本号，冲突 409；命令写审计与撤销（CRUD 类） |

### B. cross_border（待实现）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| B-1 | 发运单 | 一张发运单可含**多张采购单**（拼柜/合并发货），一张采购单也可拆到**多张发运单**；按行数量分摊，累计不得超过采购数量 |
| B-2 | 在途 | 发运单承载在途状态与里程碑（已揽收/出口报关/在途/到港/清关/入海外仓）；无实时接口时手工推进 |
| B-3 | 出口单证 | 报关/装箱/商业发票（或提单）以单据 + 附件形式归档，可下载；范围见开放问题 Q1 |
| B-4 | 海外仓收货 | 收货落 `wms.inventory.receive`（海外仓 warehouse），并回写采购单行 `received_quantity`；部分收货保持单据未完成 |
| B-5 | 对账 | 3PL 同步数据与账面差异生成对账条目，不覆盖账面 |

### C. platform_ops（待实现）

| 编号 | 需求 | 验收标准 |

| C-1 | 平台连接器 | 按已安装 `sync_akeneo` 形状（`integrations` + `data_sync`）拉取：订单、库存镜像、listing、结算单；外部 id 映射、幂等 upsert、游标可重跑 |
| C-2 | 结算与回款 | 平台回款/佣金/费用登记，可与订单关联；差异进对账 |
| C-3 | 分公司视图 | 分公司用户看到本组织的订单/库存镜像/结算，只读；总部看汇总 |

### D. 横向要求（所有模块）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| D-1 | 组织可见性 | 总部角色（授予总部组织）看到全部下级；分公司角色只看到自身；API 与页面一致，越权 403 或 404 |
| D-2 | 国际化 | 界面中英双语；新增文案必须同时落 `i18n/{zh,en}.json` |
| D-3 | 数据一致性 | 金额用定点小数；库存只由 `wms` 命令变更；跨模块只用 id + 快照/事件 |
| D-4 | 测试 | 每个新能力带自包含集成测试（成功/拒绝/跨组织/冲突），并跑通仓库验证门 |

## 验收标准（整体）

- [ ] 一条完整链路可在系统内跑通：建供应商 → 下采购单 → 付定金 → 发运（在途/单证）→ 海外仓收货 → 付尾款 → 关闭；采购单行的已收数量与 `wms` 入库一致。
- [ ] 拼柜场景：多张采购单合并到一张发运单，分摊数量累计正确且不可超发。
- [ ] 平台链：至少一个平台的数据（订单/库存/结算）经连接器进入系统，重复拉取不产生重复记录，差异进对账。
- [ ] 组织可见性三条规则在 API 与界面均可复现（总部看全部、分公司看不到上级与同级）。
- [ ] 全部门禁通过：`yarn generate && yarn typecheck && yarn lint && yarn ds:check && yarn test`。

## 开放问题

> Q1–Q3 在实现阶段三时以**可逆的默认选择**先行落地，逐条记在
> [`.ai/specs/2026-09-21-cross-border-shipments.md`](../../.ai/specs/2026-09-21-cross-border-shipments.md) 的 "Resolved assumptions" 一节（单证=最小结构化字段+附件；单证挂发运单并可选用采购单关联；里程碑手工推进、留实时接口作为后续写入方）。业务若要改口径，改这三处即可，不需要动数据模型。

| 编号 | 问题 | 影响 | 谁来定 |
|---|---|---|---|
| Q1 | 出口单证要哪几张：只归档附件，还是要结构化字段（报关单号/金额/日期）？ | B-3 的数据模型与页面 | 业务 |
| Q2 | 拼柜时单证是"一柜一套"还是"每单一套"？ | 单证与发运单/采购单的关联基数 | 业务 |
| Q3 | 货代是否有实时轨迹 API？没有就纯手工里程碑。 | B-2 实现方式 | 业务（问货代） |
| Q4 | 平台对接形态：API 直连 / 平台导出文件 / 第三方 ERP 服务商？ | C-1 适配器与凭证存放 | 业务 + 技术 |
| Q5 | 跨组织主数据分发：总部一份商品卖给所有分公司，是否要做分发/共享读？ | 是否新增独立能力 | 业务 + 技术 |
| Q6 | 提醒规则：逾期未发运、逾期未付款、库存低于阈值——触发/阈值/收件人/渠道？ | 通知与定时作业设计 | 业务 |
