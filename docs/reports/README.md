# reports — 进度汇报文档

**放**：给管理层 / 业务看的进度汇报——总体状态、逐项需求进展、待决事项与下一步计划。
一个主题一份文件，**按时间线更新同一份**（时间只写进正文的「时间线」，不进文件名），不改写成流水账。

**不放**：分阶段计划与排期（→ [`../plans/`](../plans/README.md)）、产品需求定义（→ [`../prd/`](../prd/README.md)）、
事故复盘（→ [`../pitfalls/`](../pitfalls/README.md)）、面向 agent 的执行口径（→ `.ai/specs/`）。

## 骨架

```md
# <项目> 进度汇报

> 用途 / 基准日 / 状态来源 / 更新规则

## 一、总体结论
## 二、需求状态（✅ 已完成 / 🟡 半完成 / ⬜ 未开始）
## 三、待决事项
## 四、下一步计划
## 时间线
## 证据索引
```

## 状态口径

- `✅ 已完成`：交付并实测——门禁全绿（generate / typecheck / lint / ds:check / test / build）
  且用真实数据跑通（API 实拉或浏览器），必要时一次性库集成测试通过。
- `🟡 半完成`：页面 / 接口已建但数据或口径未完全疏通（如等外部接口联调、成本未到位）。
- `⬜ 未开始`：待立项 / 待排期，含等业务决策。

状态与 `.ai/specs/**` 的 `**Status**` 行、`docs/plans/**` 的「进度」表是**同一口径**：
交付一件事实时，三处（含本目录对应文件）在同一个改动里一起更新。
