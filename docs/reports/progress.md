# 跨境 ERP 项目进度汇报

## 一、总体结论

- 采购 → 出口 → 平台运营三条业务链已在系统内闭环；购销合同、形式发票（PI）、商业发票（CI）、
  装箱单（PL）、发运单、内部 / 对外报价、产品主数据、供应商与报价、交易对手均已上线可用。
- KC / AB 主体账号系统（总部 + 俄罗斯 / 东南亚分公司）已建成并实测：数据隔离、越权拦截、总部汇总可用。
- **经营概览、财务两个模块为半完成**：页面与数据接口已建、已用真实数据跑通，但俄方实时数据未接入、
  部分成本未到位，暂不能作为最终经营口径（详见 🟡 部分）。
- 未开始：飞书接入、多维表格同步、俄语界面、WMS 轮换策略名词提示、平台真实传输层。

## 二、一期功能点状态

### ✅ 已完成（已上线并实测）

- 产品数据建模建表：商品 / 产品线 / 品类树 / 三档价格 / 变体，数据库迁移已应用。
- Excel 上传建模 + 界面手动建模：供应商报价工作簿导入（.xls / .xlsx；真实文件 69 行 / 78 行解析验证）、
  列映射模板复用、批量提升为商品（重复执行不重复建）；商品三步表单手工建档、编码规则发号。
- 产品类型建模：产品线 + 产品品类（层级树、可折叠、按组织维护）。
- 购销合同：采购 `PC-` / 销售 `SC-` 两方向流转；合同金额 / 财务金额双口径 + 差额；签发后生成并归档 Excel 合同文件。
- 采购模块：供应商主数据（`SUP-` 编码、银行信息）、供应商产品库（图片 / 价格 / 折扣）、
  报价流程打通（报价单 `SQ-` → 产品库 → 商品档案 → 采购单 `PO-` → 发运 / 收货）。
- 出口贸易模块：购销合同为主体；PI、CI、PL、发运单（`SHP-`）已上线并关联合同；
  发运单支持多采购单拼柜、在途里程碑、收货回写库存与采购行。
- 内部-外部报价：对内 / 对外两个销售入口；报价 → 订单支持「直接转换」与「引用载入」两种方式。
- 分 KC/AB 主体账号系统：组织树、角色 / 账号、可见性隔离与越权拦截已实测。
- 停用暂时用不上的功能模块：官方模块页面按需隐藏（模块与接口保留），未启用模块按需开启。
- 系统逻辑梳理：模块归属地图、数据主源与开放问题已沉淀在 `docs/dev/business-architecture.md`，
  并据此确定「复用 / 自建 / 停用」策略。
- 前端页面：全部作业页按角色分组（采购 / 出口业务-销售 / 出口-对外销售 / 出口-购销合同 / 出口-发运 /
  出口-单证 / 经营概览 / 财务 / 数据同步 / 商品主数据 / 交易对手 / 平台运营 / 基础数据）。
- 流程跑通：供应商 → 采购单 → 发运 → 收货 → 到岸成本 → 收汇 → 退税端到端链路已在全新数据库通过验证。
- 中英双语：界面、字典、打印文档与导出表头单语言渲染，并有自动化测试防止中英混排。

### 🟡 半完成 / 进行中

- **经营概览模块**（老板驾驶舱 / 月损益 / SKU 毛利 / 库存资金占用）：页面与接口已建、已跑通真实数据，
  但尚未完全疏通——俄方实时数据未接入，部分成本未到位（缺成本时先标「缺数据」），
  联调完成后才能作为最终经营口径。
- **财务模块**（台账 / 发票 / 成本 / 退税）：台账、税务发票台账、柜费用与到岸成本、退税档案均已建并实测；
  剩余：与真实业务数据的全量核对、俄方数据打通后的完整对账。
- 关联 Invoice 表单与附件：发票表单、附件上传 / 归档、图片与 PDF 预览已通；
  「附件解析」（按附件自动抽取字段）未做，需确认口径。
- KC/AB 两个订单系统打通：KC 内部销售链已通；俄方 17 个接口契约已冻结、模拟全量验证通过
  （幂等重放、失败不推进游标）；真实联调未开始（等俄方 token、金额格式最终版、联调窗口）。
- 业务人员实操反馈：多轮反馈已修复合入（界面可用性、字段口径、组织可见性等），继续按实操迭代。

- 基于多维表格字段同步至系统（与飞书一并确认口径）。

- WMS 轮换策略：中文 + 问号名词解释提示。
- 平台运营传输层（真实连接器 / 文件对接，等对接形态确定）。

- 平台运营模块：🟡 核心完成（渠道、订单镜像、结算、对账、分公司只读视图；重复拉取不产生重复数据）；
  真实传输层未做，等对接形态确定。
- 按平台划分数据与订单：🟡 按渠道归集与幂等入库已验；完整按平台口径要等真实拉单接入。
- 数据同步模块：🟡 底座已启用（运行 / 游标 / 幂等重跑 / 健康检查页）；
  俄罗斯业务接口对接按「先 supply 8、后 ads 9」顺序完成模拟全量验证，实作方案已备，等开工。

## 四、待决事项（需要确认）

1. 俄方接口：测试 / 生产 token、金额格式最终版、联调窗口与联系人。
2. 平台对接形态：API 直连 / 平台导出文件 / 第三方服务商。
3. 飞书用途与多维表格同步范围。
4. 俄语范围（界面 / 打印文档 / 对客户单据）。
5. 附件「解析」口径：是否需要自动抽取字段。
6. 经营概览 / 财务的最终口径（成本与损益计算边界）与业务核对时间。

## 五、下一步计划

1. 俄方数据联调（拿到 token 与金额格式即可开工）。
2. 财务 + 经营概览补全：口径核对 → 俄方数据接入 → 端到端对账（完整月损益 / SKU 毛利）。
3. 采购 / 出口收尾：分公司仪表盘、一次性环境全量集成测试、审计链复核。
4. 平台传输层定形态后开工。
5. 按业务实操反馈继续小步迭代。
6. 待立项排期：飞书、多维表格、俄语、WMS 提示、对象存储切换（服务开通后一条命令完成）。
