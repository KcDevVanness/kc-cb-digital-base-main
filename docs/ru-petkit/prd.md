## 背景与问题

中国业务（采购 + 外贸为主）需要对接俄罗斯 PETKIT 跨境电商数据系统。俄方要求中方先书面明确：决策目标与频率、需要的字段 / 维度清单（以便其调整 `/api/v1`）；中方负责目标系统需求描述与双方模型映射，并给出本系统架构 + 模块清单 + 接口规范（HTTP API，不含 Odoo）。

现状问题：俄方 11 个页面此前只有口头与截图片段，没有逐页取证、没有指标口径书面化、没有与中方 7 个模块的映射，无法进入 token / 仓库对接阶段。本 PRD 把“俄方系统是什么、每页能干什么、验收口径是什么”一次性写死，作为发俄方的需求描述正文。

## 目标 / 非目标

**目标**

1. 11 路由功能全部有中文定义：每页一句话定位 + 筛选维度 + 指标清单 + 展示形态 + 可判定验收标准（见功能需求 F-01…F-11）。
2. 核心指标口径全部可验算：ДРР、两种 маржа、удержания、себестоимость、CPO/CPC/CTR、средний чек、ROI、供应需求式（见口径表，算式已用页数字验算通过）。
3. 决策 × 频率 × 粒度三档（日 / 周 / 月）全部明确到“谁看什么、看到多少就动手”（见用户与场景）。
4. 本文档与同目录证据链互相引用、无断链；与本项目系统严格区分（见开放问题 Q4）。

**非目标**

- 不描述本仓库 ERP 的实现（实现见 `../prd/cross-border-erp.md` 与各模块 README）。
- 不产生俄文全文翻译（中文先行，翻译待确认后再做）。
- 不猜 `/api/v1` 快照结构：快照未到前未知项一律标 `待快照确认`，不编造 key。
- 不做大导出：样本仅单 SKU 单日 ≤50 行，用于提取列头。

## 功能需求（逐页可验收）

### F-01 `/ads` — Обзор 总览

- 功能：全系统驾驶舱。ДРР 头（расход ÷ чистая выручка）+ живыми口径 + 目标 ≤ 20% 偏离尺；按日动态曲线； расход按广告类型结构、выручка按类目结构；ТОП товаров（页注：`ДРР по товару не считаем`，Директ расход不分 SKU）。
- 筛选维度：`7 дней / 14 дней / Месяц / Всё`。
- 指标：ДРР 7,5% / 4,4% живыми；Выручка чистыми 5 006 199 ₽；Расход 376 307 ₽（219 441 ₽ живыми）；Оплачено заказов 472 / 542；Средний чек 10 606 ₽；类型结构（Смарт-баннеры 36,5% / Ретаргет 34,8% / Бренд 10,7% / Поиск 10,2% / Медийная 7,9%）；类目结构（Лотки 60,9% / Фонтаны 14,2% / Кормушки 10,9% / Наполнитель 8,4% …）；TOP（PK39_2 21,6% / PK44 17,6% / PK41_2 16,4% …）。
- 验收：路由 200 且 title 为 `PETKIT · Реклама`；页含 `Источники: Яндекс Директ · Я.Кит · Яндекс Метрика`；ДРР 验算 376307 / 5006199 ≈ 7,5%；截图 `shots/01-overview.webp` 与页一致。

- 展示：KPI 头（1 624 шт / 14 179 698 ₽；Корзин CR 34% 4 764；Переходы CR 1% 137 832；Маржа 38,3%；ДРР 11,7% / 7,3% живыми）+ 矩阵；`↓ Экспорт CSV` 为客户端生成 `Prodazhi_po_saytu.csv`。

## 对接价值分级（只排 RU 已有页面）

定义：S = 断流即停摆；A = 直接省钱 / 算钱；B = 提效；C = 存档备查。
排序：`supply ≧ costs / reprice > marketplaces / summary / export > products > types > funnel > brand`。
S：supply（缺口 → PO 草稿；在途 ETA → 收货计划；超储 → 刹车）。
A：costs + reprice（成本 → purchase 档 / 双口径；маржа → 定价）；marketplaces + summary（结算 → 对账差异队列；ОПИУ → 财务 + 发票）。
B：export（行明细 → 订单镜像）；products（站内销售 → 需求权重）；types（类型 ДРР → 调参依据，只存档）。
