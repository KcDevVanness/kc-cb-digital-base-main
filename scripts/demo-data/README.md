# demo-data — 业务形态演示数据

`seed-business-data.mjs` 按**真实业务链**在目标环境生成一套演示数据：跨境宠物用品出口
（广州凯翠国际贸易有限公司 → 俄罗斯 / 东南亚），走的是与界面完全相同的 HTTP API
（校验、服务端编号、快照、事件、索引都在），不是绕过应用的 SQL 灌数。

## 生成什么

| 层 | 内容 |
|---|---|
| 供应商 | 8 家中国工厂/贸易商（深圳小佩、东莞宠物之家、宁波超级爪爪、佛山洁宠猫砂…），品牌 `PK`/`DK`/`SP`，`SUP-####` 由命令发号 |
| 产品库 | 25 行货品（饮水机、猫砂盆、猫砂、铲子、喂食器、航空箱、配件…），含 G.W./N.W.、体积、MOQ、装箱数、折扣；每行 CNY + USD 供货价（含阶梯价） |
| 商品 SKU | 由 `product_codes` 发号（`PK-CB001`、`SP-CL002`…），台账可追溯；旧码/别名机制不变 |
| 商品主数据 | 13 个商品由产品库建档，三档价格（成本价/内部结算价/对外销售价，含阶梯与有效期），并链接目录商品（发运收货链路需要） |
| 交易对手 | 买家（俄罗斯 ООО «ПетМаркет»、ЗооТрейд，新加坡 PetJoy）、货代、报关行、银行、认证机构，含银行账户（按生产密钥加密） |
| 报价 | 4 份供应商报价（`SQ-2026-####`），含行与币种，已审批 |
| 采购 | 17 张采购单（`PO-2026-####`，业务号 `PI-2026-####`），含行、定金/付款、供应商发票；其中 5 张已发运 |
| 发运 | 5 个柜（`SHP-2026-####`：40HQ / 40HQ*2 / 20GP+40HQ / 卡派），含配载、承运人、港口、在途里程碑、报关单 |
| 合同/发票 | 6 份合同（`PC-` 采购 / `SC-` 销售，已签发/签署）+ 6 张发票（已确认，联动合同财务口径） |
| 收汇/退税 | 每个采购单一条收汇档案、每个柜一条退税档案（金额、状态） |
| 平台 | 3 个渠道（Amazon US / Ozon RU / TikTok Shop SEA）、48 条订单镜像（带柜号关联）、5 份结算（含 9 条**待处理**对账差异，另有 3 条已处理） |
| 内销 | 4 张内部调拨订单（走安装版 `sales` 引擎，单号由引擎发） |
| 汇率 | 由 `currency_policy` 的 CNY 口径 provider 抓取（`exchange_rates`），供全站 `≈ ¥` 换算 |

## 怎么跑

```bash
# 需要一个会话（登录等价，不改任何密码）：
#   TOKEN = 该用户的 JWT，ORG = 目标组织 id
BASE_URL=https://<host> TOKEN=<jwt> ORG=<organization-uuid> \
  node scripts/demo-data/seed-business-data.mjs

# 只跑某些阶段（阶段名见文件末尾 PHASES）：
ONLY=suppliers,library,products ... node scripts/demo-data/seed-business-data.mjs
```

- **幂等**：主数据按名称/编码匹配，单据按业务号或 `notes` 里的标记匹配；重跑输出 `kept` 而不是重复创建。
- **可续跑**：阶段之间的映射写在 `STATE`（默认 `/tmp/demo-state.json`），所以可以分阶段执行与核对。
- **留痕**：创建结果写在 `MANIFEST`（默认 `/tmp/demo-manifest.json`），含每个对象的 id，便于精确清理。
- **单条失败不中断**：失败项记录在 manifest 的 `failed[]`，其余继续。
- `DRY=1` 时只跳过写请求（读仍走真实接口），用于检查脚本结构。

## 前置条件（目标环境需已有）

1. 迁移已应用（部署时容器启动自动 `yarn db:migrate`）。
2. 新模块种子：`yarn mercato seed:defaults --module product_codes`（品牌/类别码表 + SKU 规则）。
3. 币种字典（`currency_policy` 的 `seed:defaults`）与 CNY 汇率（`yarn mercato currency_policy fetch-rates`）。
4. 类别码表若缺少演示用到的字母（本脚本用 `CL/TP/LB/LS/CB` + `FD/AC`），需先在字典库补 `FD`（喂食饮水）/`AC`（配件）。

## 边界

- **不碰账号**：不创建/修改任何用户、角色或密码；脚本只用调用者自己的会话。
- 演示数据带「演示数据」标记（`notes`）或固定业务号前缀，便于识别与清理。
- 附件类字段（报关单扫描件等）只写单据行、不传文件，所以导出清单里的附件勾选为空。
