# Execution plan — the `dev` integration trunk (2026-09-29)

## Goal

Give parallel agent units one long-lived integration trunk: units branch from `origin/dev` and open
their PR against `dev`; a wave lands on `main` as a single `dev → main` PR, after which `dev` is reset
onto `main`. "Which line is this work on" becomes readable at a glance, without re-creating the two
failures this repository has already paid for:

- a trunk that keeps taking PRs after its squash merge strands that content (270 paths on
  `origin/feat/cross-border-erp` — `.ai/lessons/squash-merged-base-strands-later-prs.md`);
- a trunk that silently falls behind `main` (PRs #21/#22 exist only to reconcile that for
  `production`).

What makes a permanent `dev` different from those two casualties is one safety property: **`dev` never
holds content `main` cannot reach, and its drift is loud.** Concretely: (a) `dev` is the integration
place for the units of the current wave, never a base for work that outlives a wave; (b) after every
landing, `dev` is reset to `origin/main`; (c) `yarn branches:cleanup` reports trunk drift — unlanded
path count, oldest unlanded commit, and ahead/behind counts against `origin/main`.

## Scope

- `origin/dev` created at `origin/main`, with branch protection (PR required, `validate` +
  `guard-tree` required, linear history, no deletions).
- `.ai/agentic.config.json` — `baseBranch: "dev"`, so every pipeline skill opens unit PRs against the
  trunk instead of `main`.
- `scripts/git/branch-cleanup.mjs` — keep `dev` out of the deletion candidates, derive the cover ref
  from the configured base branch, and add the trunk drift report.
- `AGENTS.md` + `docs/dev/parallel-development.md` — base rule, wave landing, reset command, exit
  checks, hotfix exception.
- Lessons: amend `squash-merged-base-strands-later-prs.md` (its "every PR's base is `main`" rule gains
  the trunk exception) and add the trunk-discipline record.

Non-goals: no module/app code; no CI workflow change (`validate.yml` / `guard-tree.yml` already run on
every PR target — `.ai/lessons/gate-must-cover-every-pr-target.md`); `production` protection and the
PR #21/#22 reconciliation are untouched; hotfixes keep `main` as their target.

## Risks

- **A permanent trunk can strand content** (the `feat/cross-border-erp` shape). Mitigated by the reset
  after every landing, the trunk report, `dev` staying out of the deletion candidates, and `dev`
  counting as a cover ref only while it is the configured base branch.
- **Squash-only `main`**: a wave lands as one commit, so per-unit subjects do not enter `main`'s
  history — keep waves small (one spec slice) and enumerate the units in the wave PR body.
- **Hotfix latency**: a `fix/` unit that must reach `main` now bases on `origin/main` explicitly and
  says so in its `## Assumptions`; the pipeline's configured base is `dev`.
- `.ai/skills/**` overrides describe `baseBranch` as `"auto"`; they are harness-managed and stay that
  way — `.ai/agentic.config.json` is authoritative, and `docs/dev/parallel-development.md` records
  the deviation.
